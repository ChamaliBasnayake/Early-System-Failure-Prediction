# Phase 6 — generalisation experiments and protocol controls (validation split)

Source of every number: `results/validation_eval/conditions_validation.md` (generated by `src/models/evaluate_conditions.py --split validation`).
Retraining runs: `scripts/phase6_retrain.ps1` (final configuration `configs/lstm_semantic_v1.yaml`, seed 11, N = 5).
Thresholds for the test evaluation were frozen by this run into `results/thresholds_final.json`.

## F6.1 The final ANN beats the strongest tabular baseline on the primary metric at every lead time
Validation PR-AUC (mean ± sd over seeds 11/22/33; prevalence 1.1–1.7 %):

| N (min) | trivial | confound LR | XGBoost (content+history) | initial ANN (template LSTM) | final ANN (semantic LSTM) |
|---|---|---|---|---|---|
| 1 | 0.0113 | 0.0179 | 0.0266 | 0.0236 | **0.0285 ± 0.0021** |
| 5 | 0.0113 | 0.0165 | 0.0238 | 0.0305 ± 0.0115 | **0.0322 ± 0.0004** |
| 15 | 0.0120 | 0.0165 | 0.0226 | 0.0292 | 0.0249 ± 0.0103 |
| 30 | 0.0166 | 0.0233 | 0.0213 | 0.0329 | **0.0400 ± 0.0056** |

XGBoost retains the best ROC-AUC at N = 1 (0.697 vs 0.669). The frozen-text embedding removed most of the seed variance of the template LSTM (sd 0.0004 vs 0.0115 at N = 5). History-only features are at or below chance (ROC 0.43–0.52): past failures of a midplane do not predict its next one. Inference costs 0.36 ms/window on CPU for the ANN vs 0.01 ms for XGBoost; training 24–45 min vs 10–30 s.

## F6.2 The signal is real but not operable at 1 % FAR
At the 1 % false-alarm threshold (≈14 alarms per midplane-day) the models catch 0–7 % of incidents; at 0.1 % FAR essentially none. PR-AUC is 2–3× prevalence and ROC-AUC ≈ 0.68, i.e. a diffuse ranking signal, not a sharp alarm. The report must state this plainly; the leakage-controlled protocol makes it visible, and that is the contribution.

## F6.3 The model is not an alert-chaser
False-alarm rate of the final ANN on *hard negatives* (alert-rich windows with no failure after them) is 0.00–0.07 % against 0.24–0.95 % on ordinary negatives. The model fires *less* on noisy windows, consistent with Phase 3 (positives occur in quieter-than-usual periods; global volume features carry 50–64 % of XGBoost gain).

## F6.4 Generalisation to unseen machines: no penalty
Model trained with 13 racks removed (incl. the pseudo-racks `NULL` and `UNKNOWN_LOCATION`, i.e. lines without a parseable location): on the never-seen racks PR-AUC 0.067 / ROC 0.649 (26 positives); the all-rack model scores the same windows 0.024 / 0.671. The difference is within the noise of a 26-positive subset; what matters is the absence of any degradation. The precursor signal is not rack-specific.

## F6.5 Generalisation to unseen failure types: generic signal for KERNMC, type-specific for KERNRTSP (one incident)
Leave-one-category-out at N = 5: the model that never saw KERNMC ranks KERNMC positives as well as the model that did (PR-AUC 0.0123 vs 0.0137; ROC 0.639) → the usable signal is ambient system state, not a KERNMC signature. For KERNRTSP the all-category model reaches 0.249 but the held-out model only 0.007 — a type-specific precursor that does not transfer — but validation holds a single KERNRTSP incident, so this is a hypothesis for the test set (KERNRTSP 50 and KERNSOCK 38 episodes overall). KERNDTLB has no validation incidents and can only be assessed on test.

## F6.6 Protocol controls — the central methodological result
| protocol | XGBoost PR-AUC N=1 | N=5 | N=15 | N=30 |
|---|---|---|---|---|
| random window split (as in most prior BGL work) | **0.581** | **0.582** | **0.581** | **0.646** |
| chronological split, transductive templates (Drain on all data) | 0.027 | 0.023 | 0.023 | 0.025 |
| honest: chronological split, templates fitted on train only | 0.027 | 0.024 | 0.023 | 0.021 |

A random split inflates the same model on the same features by ~25×: sibling windows of one incident (the five positive offsets, the same midplane-hour) fall on both sides of the split and the model memorises incidents instead of predicting them. Transductive templates change nothing on validation because validation UNK is only 2.8 %; the same control is run on the test split in Phase 7, where UNK is 61 % after the October 2005 software upgrade.

## Decisions taken on this evidence (before the test run)
1. Final ANN stays the semantic LSTM, v1 hyper-parameters (chosen in Phase 5 on mechanism; F6.1 confirms on validation).
2. Operating points reported on test: 0.1 % and 1 % FAR with thresholds frozen from validation (`results/thresholds_final.json`); no threshold is re-chosen on test.
3. Test evaluation = one run of `evaluate_conditions.py --split test` (all models, all N, held-out-category and held-out-rack models, transductive control) plus `gemini_eval.py --split test` on the fixed 300-window sample with the prompt selected on validation.
